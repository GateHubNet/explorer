# NFT Pages (E8) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve `/{net}/nfts`, `/{net}/nfts/sales`, a collection (`/{net}/nfts/{issuer}[/{taxon}]`), an NFT (`/{net}/nft/{ID}`) and its link-preview image from D3's routes and the node, behind the `NFTS` switch; make every NFT id the explorer shows (sentences, details, objects, holdings, search) lead to its page; and build the program's shared coverage pieces (`checkCoverage`, `coverageNote`, `CoverageNote`), its 64-hex search sequence and the header's NFTs item.

**Architecture:** As E5's AMM pages: pure URL and link modules in `app/domain/` (`nft-params.ts`, `nft-link.ts`, `nft-id.ts`); typed and shape-checked calls in `app/server/data-api.ts` and `node-rpc.ts`; pure view builders in `app/server/` (`nfts-view.ts`, `nft-collection-view.ts`, `nft-view.ts`); routes under `:net` that validate, redirect to the one canonical URL, call the data API (and, for an NFT the index lacks, the node) side by side under E2's card deadline, and hand the answers to the builders; and pages that only draw. No page polls. The upstream answers are fixtures: derived from D3's recorded NFT ledgers by a port of D3's rules, plus synthetic aggregates, pinned to the D3 commit.

**Tech Stack:** React Router 8.4 (framework mode) on Cloudflare Workers, React 19, TypeScript, `bignumber.js`, `ripple-address-codec`, E2's chart kit, Vitest (`unit`, `components` with happy-dom, `worker`, `worker-off`, E7's `worker-sandbox`), Playwright with axe.

**Spec:** `docs/superpowers/specs/2026-10-24-nft-pages-design.md` ("spec §n", "decision n"); its data is D3, data-api `docs/superpowers/specs/2026-10-17-nft-data-design.md` ("D3 §n"), as built by data-api `docs/superpowers/plans/2026-10-17-nft-data.md`. - **Edge classes** (spec §9): the list and older sales, first page, `minute`; any page behind a marker `MARKER_PAGE_CLASS`; a collection `minute`; an NFT `live`, burned `slow`, from the network `short` kept 60 s (`CACHE_CLASSES.minute.edgeTtl`, as E5's network pool); redirects, 404s and form errors `short`; the lower-case-id and taxon 302s `immutable`; the image `slow`, from the network `short` 60 s. A degraded answer (a card failed) is served and not stored (`markDegraded`).
- **Subrequest classes** (spec §2.2, §3.2, §4.3): `last_validated` kept `HOME_CALL_TTL_SECONDS`; the live `nft_volume`, the collections list and a collection `minute`; the daily `nft_volume` and the collection's stats `slow` kept `PERIOD_CALL_TTL_SECONDS` (300 s); `nft_sales`, the tab lists, `nft`, offers, history, an account's NFTs and the node's NFT readers `live`, and `MARKER_PAGE_CLASS` behind a marker.
- **Loading:** no polling, no `clientLoader`, no `holdFailure`. Card-level calls start side by side, each raced with `byDeadline(work, start + CARD_DEADLINE_MS)` (a late part rejects with `TooLate`, "took too long"), all awaited with `Promise.allSettled`; each failed card is `logProblem`ed and `markDegraded`. A "Cannot GET" (an API without D3) is kind `server`: a failed card or a 503, never a stored 404. `nft not found` and `collection not found` stay `not_found`.
- **One URL per view:** a query that is not exactly its view's canonical form is a 302 (`cacheClassHeaders("short")`) before any call. Everything a URL carries is validated before any upstream call.
- **Words:** NFT vs URIToken by `net.id` (`nftWords`); a network's name from the layout's network (`network.name`, `network.longName`, E7), never a literal "XRPL", "XRP Ledger" or "Xahau" in copy (E7 §16), so the sandbox says "XRPL Testnet". The glossary's words (NFT, NFT owner, collection holder, sale, transfer, royalty; never "collectible", "creator fee", "holder" for one NFT).

## Review Focus

1. **Production has `NFTS` off.** Every NFT id must be plain monospace text (shortened, full id in `title`), every collection plain text, the header item and the account tab "soon", `?tab=nfts` a 302 without a call, every NFT route and image a 404 without a call, and search must ask no NFT question. Pinned by Task 2's `nft-link.test.ts`, the off cases of Tasks 8, 10, 12, 13, 14 and 15 in `test/worker/nfts-off.spec.ts`, and Task 16's completion of it.
2. **An NFT the index lacks, against a node that is not Clio or that fails.** `unknownCmd`/`notImpl` must be `not_found` (logged once per Worker instance) so the page is a 404 only because the node also says so; a node failure (5xx, 429, malformed) or an index failure must be a 503 that is not stored, never a stored 404. Pinned by Task 11's `nftModeOf` table and Task 12's `nft.spec.ts` mode cases.
3. **A 64-hex search that is both a transaction and an NFT, or an NFT only the node knows.** Two found is the choice page; an NFT only on the node is a 302 to its page; a failed index question never sends the visitor to the node's answer instead; a found answer wins over another question's failure. Pinned by Task 15's `resolve.test.ts` and `search.spec.ts`.
4. **Coverage that is incomplete, without `from_ledger_index`, or malformed.** Each list and figure shows its own note with the ledger as a link; without `from_ledger_index`, "The index does not hold this history yet."; a `coverage` that is not the shape (a string `complete`, a negative ledger) makes the answer a server error, never a page. Pinned by Task 1's `coverage.test.ts`/`nft-shape.test.ts`, Task 4's `coverageNote` cases and the notes of Tasks 7, 9 and 11.
5. **A URI that is not text, or text that looks like a link** (`javascript:alert(1)`, `https://…`, `ipfs://…`, control characters, 256 bytes, empty). It is shown decoded as text or as hex, never as a link, never fetched. Pinned by Task 3's `uriText` tests and Task 12's `it('draws the URI as text, never a link')`.

## Rulings

1. **D3's paths go straight into `PATHS`**, not through `PENDING_PATHS` (spec §11 assumed the explorer might be built first): D3 is complete before E8 starts and Task 1 syncs its document.
2. **The recordings are copied from D3's sets** (`packages/shared/test/fixtures/xrpl/nft`, `xahau/uritoken` at `PIN`) instead of being recorded again (spec §14 "by the recorder of the existing ones"): the same recorder made them, they hold every case E8 lists, and the port is then checked against D3's own tests on the same transactions.
3. **`findHash` takes `{ net, nfts }`**: the node's NFT question differs by network (`nftInfo` / `uriToken`), and the questions are an options object so E10 adds `ledgerObjects` and E14 its 48-hex shape without changing a call site's meaning.
4. **"expired" is judged against the loader's time** (`now`, unix seconds), not "the close time of the ledger #1 was read at" (spec §4.2): D3's NFT answer carries no ledger time, and the page is `live` (5 s).
5. **"read from the network at ledger #N"**: N is `nft_info`'s `ledger_index`, which Clio sets to the ledger of the NFT's newest change (checked 2026-10-24: 107671930 for an NFT read at a later head); the owner is that ledger's and still current.
6. **The featured NFT's history is padded** with seeded synthetic older offer events (marked in PROVENANCE), so that two history pages exist: no recorded NFT has more than a few events.
7. **The transaction page's `nft` segments carry no `serial`**: a serial means little without its collection in a sentence; the short id is shown. The `serial` field stays for later use.
8. **`nftWords` and `collectionLabel` live in `nft-params.ts`**, and `nftSalesHref` takes `(net, { marker })` like the other hrefs.
9. **The intro and every network name read `network.name` / `network.longName`** (E7 §16), so the sandbox says "XRPL Testnet"; the NFT/URIToken words follow `net.id`.
10. **The list's average sale** is rounded to whole native units half up. The collection's 30-day average divides Σ `volume_native` by the days' converted sales, each day's being `volume_native ÷ avg_price_native` rounded to a whole number: D3's stats days carry no count of converted sales (`sales_count` counts every sale).
11. **Generated files under `data-api/accounts/`** (consistency pass): that directory is hand-written (`isHandWritten`), and `generate()` may write none of its files; the NFT holdings files the generator writes there are named by `isNftGenerated` and taken out of `isHandWritten`, as the analytics answers are. E10 and E14 write their account files there by hand.
