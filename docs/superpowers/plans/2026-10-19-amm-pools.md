# AMM Pools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `/{net}/amm`, `/{net}/amm/{pool}` and the pair redirect `/{net}/amm/{base}/{counter}`, server-rendered from the data API's AMM routes and the node's `amm_info`, behind the `AMM_PAGES` switch, with every pool link in the explorer following that switch.

**Architecture:** `app/domain/amm-params.ts` (pure, browser-safe) owns the URL forms and `poolLink`; `app/server/amm-view.ts` (pure) turns upstream answers into page data; three routes under `:net` validate, redirect to the one canonical URL, call the data API and the node side by side under E2's 4.5 s card deadline, and hand the data to `AmmListPage`, `AmmPoolPage` and `NoAmmPage`, which only draw. The AMM upstream answers are generated fixtures (derived from the recorded AMM ledgers, synthetic for aggregates) that follow `feat/amm-data` at a pinned commit.

**Tech Stack:** React Router 8.4 (framework mode) on Cloudflare Workers, TypeScript, bignumber.js, ripple-address-codec, E2's hand-written chart kit, Vitest (`unit`, `components`, `worker`, `worker-off` projects), Playwright with axe.

**Spec:** `docs/superpowers/specs/2026-10-19-amm-pools-design.md` (the plan argues from the spec; executors read both). The owner approved its "Owner decisions to confirm" table as written.

**Branch:** `feat/explorer-pages` of `/Users/golobitch/github.com/GateHubNet/x-explorer`. E5 is built last: the E2, E3, E4 and E6 plans are built on this branch before Task 1 starts (D1 and D2 before them). The data API's AMM routes exist only on `data-api-new` branch `feat/amm-data`, unmerged and owned by another session: read it only with `git -C /Users/golobitch/github.com/GateHubNet/data-api-new show c3e23026b3405fc2fd27fc897e724df4dfe106f1:<path>`; never check it out, never edit it.

## Global Constraints

- **Pinned data API commit:** `feat/amm-data` at `c3e23026b3405fc2fd27fc897e724df4dfe106f1` (`c3e2302`). Types, shapes, key orders and fixtures follow its `docs/api-reference.md` (section "AMM", and `/v2/network/amm_volume`, `/v2/exchanges/{base}/{counter}`) and `apps/api/src/amm/amm-objects.ts`.
- **Switch:** `AMM_PAGES`, E2's mechanism as it is: `"on"` or `"off"` per environment; top level (development, tests) `"on"`, `staging` and `production` `"off"`. In `Features` it is `ammPages`. A route shows the pools when `net.features.ammPages && net.hasAmm`, Xahau's explanation when `ammPages` and not `hasAmm`, and the 404 "We couldn't find the AMM pages on {network}" (class `short`, no call) when off.
- **`AMM_DATA`** stays E2's: it gates the AMM-derived parts of the other pages, and E5 does not read it at run time. `AMM_PAGES` goes on in an environment only where `AMM_DATA` is on there; the pre-deploy guard refuses a build that has `AMM_PAGES` on and `AMM_DATA` off (Task 1).
- **D2b items stay out:** no 24 h fee figures on the list, no rolling per-pool fee; the cards that read the pool's day rows say `"A day without rows may not be computed yet."` (one constant, `NOT_COMPUTED_NOTE`).
- **Edge classes:** list (first page, behind a marker, filtered or not) `live`; list with an asset that does not parse `short`; `/xahau/amm` `slow`; pool first page `live`; deleted pool `slow`; pool from the network `short` with TTL 60 s; pool behind a marker `MARKER_PAGE_CLASS`; pair redirect `slow` to a live pool, `short` to a deleted one; canonical redirects (302) and 404s `short`; degraded answers and 5xx not stored. No new class, no new constant.
- **Subrequests:** `last_validated` `live` kept 2 s (`HOME_CALL_TTL_SECONDS`); `/v2/amm/pools`, `/v2/amm/pools/{pool}` and the live `amm_volume` `minute` (E3's, kept 60 s); 30-day `amm_volume`, the pool's day rows and the candles `slow` kept 300 s (`PERIOD_CALL_TTL_SECONDS`); node `amm_info` `live` (5 s); tab lists `live`, `MARKER_PAGE_CLASS` behind a marker (`listClass`); the create event `slow` (1 h).
- **No live refresh**, no `clientLoader`, no `holdFailure` on either page. Nothing is streamed or deferred: `Promise.allSettled`, every card-level call and chain raced with `byDeadline(work, start + CARD_DEADLINE_MS)` (`app/server/deadline.ts`, 4.5 s from the start of the loader; past it the part rejects with `TooLate`, the reason `"took too long"`). Every failed card is logged with `logProblem` and marks the request degraded with `markDegraded`.
- **One URL per view:** a query string that is not exactly the canonical form is a 302 (`cacheClassHeaders("short")`) to it. Everything a URL carries is validated before any upstream call.
- **404 kinds:** E2's route-missing rule as it is: a 404 whose message starts `Cannot GET ` is kind `server` (503 or a failed card, never stored); `pool not found` stays `not_found`.
- **Orientation:** every displayed pair is E3's `naturalOrientation` (`"XRP / RLUSD"` on the page, `"XRP/RLUSD"` in breadcrumbs, titles and 404s); `canonicalPair` only for talking to the API.
- **Exactness:** every number in page data is a string made from the API's or node's text, or with BigNumber; JSON numbers become strings with `String(n)`. No float reaches a label. The list shows `compactNumber`; the pool page shows exact amounts.
- **Browser bundle:** pages never fetch; `AmmListPage.tsx`, `AmmPoolPage.tsx`, `NoAmmPage.tsx` and `amm-params.ts` import nothing at run time from `app/server`, `app/domain/describe`, `app/domain/parse`, `app/domain/asset` or `ripple-*`. JS budget 150,000 B gzip per page; the pool page's target is 145,000 B.
- **Accessibility:** statuses are icon and text; targets 44 px (period links, tabs, pager, copy buttons, the form's button and checkbox label); tables are `DataTable`; coins `aria-hidden`; WCAG 2.2 AA, axe gate: no violation of impact serious or critical.
- **Shared pieces are used as they are**, by the names and files of the table below; never a second copy. A kit component or shared file gains a prop or an export only as a growth step a task names, with a default that keeps its owner's behaviour. Earlier plans are referred to by piece and file, never by task number.
